# ADR-0002：圆角、无阴影的卡片语言

状态：已采用（2026-09-23）。用户指示「不要用阴影，参考 fuwari 的卡片 + 圆角设计」。

## 背景

首版按用户提供的 `ui.png` 确立了「直角矩形 + 半透明面板 + 柔和阴影」的卡片语言，并写进规范：内容条目之间不用分隔线，靠表面、间距与阴影分组；几何背景面板同样用柔和投影表达前后关系。这套做法下，层次的表达依赖阴影。

用户随后指定参考 [fuwari](https://fuwari.vercel.app/)：卡片为**圆角、无阴影**，层次靠卡片底色与页面底色的明度差表达。两者不能并存——阴影与「无阴影」、直角与圆角在同一套表面上无法同时成立。

## 决定

1. **全站不使用任何阴影**：内容卡片、面板、页头强调层、浮层、模态层、悬停反馈以及首页背景几何面板都不再有 `box-shadow`；`--elev-*` 与 `--backdrop-shadow*` 令牌一并删除。
2. **圆角刻度**：卡片与面板 16px、按钮与输入 8px、小芯片 6px，图片随卡片圆角裁切（对齐 fuwari 的 `--radius-large: 1rem` 与 `rounded-lg`）。
3. **层次改由明度阶梯表达**：浅色下页面底色比卡片暗一档，深色下卡片比页面底色亮一档；阶梯值在五份配色 × 浅色/深色共 10 种组合下统一校验。
4. **悬停反馈改为颜色与缩放**：卡片底色变一档、标题转强调色、封面轻微放大；键盘焦点用 `focus-within` 给出同样的三项反馈。不再有位移与投影。
5. **浮层与模态层改用 1px 边界**：失去阴影后，浮层、模态与页头吸附态用 `--c-line` 的 1px 边界保持可辨（控件边界是规范允许的线条，不属于「内容容器装饰线」）。
6. **卡片根不裁切**：`overflow: hidden` 会把 `focus-visible` 的轮廓切掉，因此圆角裁切下沉到封面容器与装饰内层元素，卡片根保持 `overflow: visible`。

## 后果

- 页面底色与内页背景整体压深/压暗一档：浅色 `--c-canvas` 由 `#eef3f8` 变为 `#e8eef5`，深色内页背景由「比卡片亮」改为「始终比卡片暗」。这是让卡片在无阴影时仍能浮起的必要条件，不是附带的美化。
- 次级文字 `--c-muted` 随之微调为 `#536880`，以在五份配色下都保持对底色的 4.5:1 对比度（原值在压深后的底色上掉到 4.48:1）。
- 浅色直角、深色阴影这两个原基准特征被替换；`ui.png` 仍是构图与气质的参考，但不再作为直角与阴影的依据。
- 产物校验新增「应用 CSS 不得声明 `box-shadow`」与「必须产出圆角工具类」两条断言，上一轮的「必须有阴影工具类」断言被替换。
- 背景几何的前后关系改由填充明度差承担，原先靠投影拉开的层次需要在像素层面继续守住（现有相邻面板明度差断言继续生效）。
- 归档时间轴的虚线、空心圆与节点不受影响：它是语义性的时间顺序表达，与卡片描边无关。

## 备选方案

- 保留阴影、只把卡片改成圆角：改动最小，但不满足用户「不要用阴影」的要求。
- 只给内容卡片去阴影、保留背景与浮层阴影：层次表达会出现两套规则，规范难以自洽，用户已选择「全站彻底无阴影」。
