# 内容维护指南

## 新增文章

创建 `content/posts/my-entry/zh.md`，目录名使用小写英文、数字和连字符。目录标识组成永久链接，同一目录下的 `en.md` 是对应英文版本。

```yaml
---
title: 今天注意到的一件小事
publishedAt: 2026-09-23T08:00:00Z
kind: article
layout: illustrated
tags: [日常, 观察]
summary: 可以手写这一句，也可以删除此字段使用自动摘要。
cover: ./morning.png
coverAlt: 清晨落在窗边的光
draft: true
---
```

随后使用普通 Markdown 写正文。标题、日期、用途、展示形式及至少一个标签必填。日期显示统一使用 UTC 日历日期，避免不同构建环境出现日期偏移。修改文章目录名会改变 URL，应同时处理旧链接。

## 用途与展示形式

`kind`：`article`（文章）、`diary`（日记）、`note`（学习笔记）。

`layout`：`text`（文字）、`illustrated`（图文）、`gallery`（图片分享）。两者可以组合，例如图文日记使用 `diary + illustrated`。画廊至少需要一张正文图片。

标签是可读名称，同一个语言内保持拼写一致。支持中文和含空格的英文标签；不能包含 `/ # ? %`，避免路由歧义。

## 图片

图片与文章放在同一目录，用 `![有意义的替代文字](./morning.png)` 引用。主要内容图片使用本地资产以便构建校验与优化；不要把私人图片放进会直接复制到产物的 `public/`。

没有 `cover` 时自动采用正文第一张图片；没有图片时使用文字卡片。纯图片分享可以只写标题、元信息和图片，不必补摘要。图片说明可以写在图片后的斜体段落中。

## 摘要、精选和置顶

- `summary` 非空时直接使用；否则从正文提取最多 160 个字符，忽略图片及代码块。没有可提取文字时省略。
- `featured: true` 将文章加入精选候选，首页选取其中发布日期最新的一篇；没有候选时使用最新文章。
- `pinnedOrder: 0` 置顶，数字越小越靠前。同值按发布日期倒序。去掉字段即恢复时间排序。
- `demo: true` 显示演示内容标记，真实文章应删除该字段或设为 `false`。

## 译文

将同一篇内容的译文保存为相同目录中的 `en.md`。标题、正文、摘要和标签自行翻译。每个版本有独立发布状态；没有译文完全合法，系统不会自动翻译或复制原文。

中文和英文列表、RSS 和搜索分别只收录本语言已发布内容。译文发布日期由各文件记录。

## 预览与发布

1. 写作时保留 `draft: true`，运行 `pnpm dev` 本地查看。
2. 准备发布后将 `draft` 改为 `false` 或删除字段。
3. 执行 `pnpm content:check`；错误会指出文件和原因。
4. 执行 `pnpm build`，然后 `pnpm preview --port 4330` 检查真实产物和搜索。
5. 按自己的 Git 发布流程提交内容并触发 Pages 构建。

首版没有定时发布：`publishedAt` 用于展示和排序，实际公开状态由 `draft` 决定。写入未来日期不会自动延迟发布。
